# ADR-0003: Минимальная версия Go — 1.26

## Статус

Accepted

## Контекст

Нужно определить версию Go для `go.mod`, локальной разработки и CI. Решение должно учитывать:

- актуальную поддержку security fixes;
- стабильность стандартной библиотеки;
- доступность инструментов для Ubuntu;
- отсутствие необходимости использовать самую новую возможность языка;
- учебную цель проекта.

На дату принятия решения актуальной стабильной веткой является Go 1.27. Официальная политика Go поддерживает релиз до появления двух следующих major releases, поэтому текущая поддерживаемая пара — Go 1.27 и Go 1.26. Источник: [официальная история релизов Go](https://go.dev/doc/devel/release).

## Краткая справка: `go` directive

В `go.mod` строка `go 1.26` задаёт минимальную версию языка и tooling, на которую рассчитан модуль. Это не означает, что приложение обязано использовать все возможности Go 1.26.

Версия компилятора и версия языка связаны, но не полностью идентичны: compiler может быть новее, чем значение `go` directive, если код сохраняет совместимость с указанной версией.

## Решение

Минимальная поддерживаемая версия Go — 1.26.

Локальная разработка может использовать более новую стабильную версию, включая Go 1.27, но код проекта не должен требовать возможностей, появившихся только после Go 1.26, без отдельного ADR.

В CI будет проверяться Go 1.26 как минимальная версия. Дополнительная проверка на текущей стабильной версии может быть добавлена после появления базового workflow.

## Причины выбора

### Поддерживаемая версия

Go 1.26 входит в актуальную поддерживаемую ветку. Это даёт разумный баланс между обновлёнными исправлениями и стабильным API.

### Учебный проект не требует bleeding-edge API

Основные задачи `cocker` используют:

- `os`;
- `os/exec`;
- `syscall`-related APIs через `golang.org/x/sys/unix`;
- `context`;
- `sync`;
- `encoding/json`;
- `testing`;
- стандартные filesystem и network packages.

Для них нет необходимости привязывать архитектуру к Go 1.27.

### Удобство восстановления знаний

Ограничение на Go 1.26 уменьшает соблазн решать архитектурные задачи новыми экспериментальными API. Мы будем разбирать базовые механизмы языка и runtime, которые важнее конкретной версии.

## Последствия

### Положительные

- проект запускается на поддерживаемой версии Go;
- CI имеет чёткий минимальный baseline;
- новые языковые возможности не становятся скрытой зависимостью;
- легче проверять совместимость с Ubuntu environments.

### Отрицательные

- новые возможности Go 1.27 нельзя использовать без отдельного решения;
- часть новых исправлений и API текущего компилятора не будет обязательной;
- после окончания поддержки Go 1.26 потребуется обновить baseline.

## Правила использования возможностей Go

1. Если возможность есть в Go 1.26, её можно использовать после проверки, что она улучшает код.
2. Если возможность появилась позже Go 1.26, сначала нужно обсудить, нужна ли она проекту.
3. Версия внешнего модуля `golang.org/x/sys` фиксируется отдельно в `go.mod` и обновляется независимо от версии языка.
4. Изменение минимальной версии оформляется новым ADR или заменой статуса этого решения.

## Альтернативы

### Go 1.27 как минимальная версия

Отклонено для текущего этапа: проекту не нужны специфические возможности 1.27, а baseline будет обновлён без практической выгоды.

### Go 1.25

Отклонено: ветка уже не является частью актуального поддерживаемого baseline после появления Go 1.27.

### Поддерживать несколько старых версий

Отклонено для MVP: матрица CI и диагностика платформенных проблем станут шире, хотя runtime всё равно ориентирован на современные Linux mechanisms.

## Проверка решения

После создания модуля нужно проверить:

```text
go version
go env GOMOD
go test ./...
```

CI должен явно запускать тесты на минимальной версии Go 1.26.
