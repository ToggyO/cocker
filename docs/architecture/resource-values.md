# Resource Values

## Статус документа

- Статус: draft
- Версия: 0.1
- Связанный документ: [`docs/architecture/container-spec.md`](container-spec.md)

## Назначение

Документ определяет пользовательские форматы resource limits и их внутреннее представление до записи в cgroup v2.

## Краткая справка: resource limit и usage

Resource limit — верхняя граница, которую runtime просит kernel применить к группе процессов.

Usage — фактическое потребление ресурса. Например, `memory.max` задаёт memory limit, а `memory.current` показывает текущее потребление.

В `ContainerSpec` храним limit. Usage относится к observed state и не является частью пользовательской конфигурации MVP.

## Memory

### Пользовательский формат

Memory задаётся строкой с binary unit:

```text
512B
64KiB
256MiB
1GiB
```

Допускается отсутствие суффикса, которое означает bytes:

```text
1048576
```

Суффиксы `KB`, `MB` и `GB` в MVP не поддерживаются, чтобы не смешивать decimal и binary semantics. Значение `256MiB` равно `256 * 1024 * 1024` bytes.

Специальное значение `max` можно поддержать для явного снятия лимита, но для MVP отсутствие поля означает отсутствие явного ограничения. Поэтому `max` пока отклоняется во избежание лишних вариантов поведения.

### Внутренний формат

После parsing memory хранится как `uint64` bytes:

```go
type ResourceSpec struct {
	MemoryBytes *uint64
}
```

Pointer отличает «лимит не задан» от заданного лимита со значением.

### Validation

- значение должно быть целым;
- значение должно быть больше нуля;
- multiplication by unit не должна переполнить `uint64`;
- значение должно быть совместимо с ограничениями kernel и cgroup filesystem.

## CPU

### Краткая справка: cgroup v2 `cpu.max`

В cgroup v2 CPU quota задаётся в файле `cpu.max` двумя значениями:

```text
quota period
```

Например:

```text
50000 100000
```

означает, что группа может использовать CPU 50 миллисекунд за период 100 миллисекунд, то есть примерно половину одного CPU.

### Пользовательский формат

CPU задаётся в millicores:

```text
500m   # 0.5 CPU
1000m  # 1 CPU
2000m  # 2 CPU
```

В CLI допускаем флаг:

```text
--cpus 500m
```

В JSON:

```json
{
  "resources": {
    "cpus": "500m"
  }
}
```

### Внутренний формат

Используем явные quota и period:

```go
type CPUQuota struct {
	Quota  uint64
	Period uint64
}
```

Для MVP выбираем фиксированный period `100000` микросекунд. `500m` преобразуется в quota `50000`.

Формула:

```text
quota = millicores * period / 1000
```

### Validation

- значение должно иметь суффикс `m`;
- millicores должно быть больше нуля;
- результат quota должен быть больше нуля;
- значение должно помещаться в `uint64`;
- период не меняется пользовательским параметром в MVP.

## Process count

### Пользовательский формат

Количество процессов задаётся положительным целым числом:

```text
--pids 64
```

JSON:

```json
{
  "resources": {
    "pids": 64
  }
}
```

### Внутренний формат

```go
type ResourceSpec struct {
	PidsLimit *uint64
}
```

Значение записывается в cgroup v2 `pids.max`.

### Validation

- значение должно быть больше нуля;
- дробные и отрицательные значения запрещены;
- `0` не используется как способ запретить все процессы, поскольку контейнеру нужен хотя бы основной процесс.

## Ошибки parsing и validation

Ошибки должны различать:

- неизвестный unit;
- пустое значение;
- отрицательное значение;
- переполнение;
- недопустимое zero value;
- конфликтующие источники CLI и JSON;
- невозможность применить уже корректное значение из-за kernel или permissions.

Parsing errors относятся к config layer. Ошибка записи `memory.max` или `cpu.max` относится к platform/runtime layer и не должна маскироваться под ошибку формата.

## Причины выбора

- binary units однозначно описывают memory bytes;
- millicores проще для пользователя, чем ручное знание cgroup quota/period;
- фиксированный CPU period уменьшает число параметров MVP;
- внутренние типы соответствуют kernel interface;
- `nil` позволяет отличить отсутствующий limit от нулевого.

## Альтернативы

### Memory в десятичных `MB` и `GB`

Отклонено для MVP: в системах часто смешиваются decimal и binary meanings. Явные `MiB` и `GiB` уменьшают неоднозначность.

### CPU в долях, например `0.5`

Отклонено: millicores лучше избегают floating-point parsing и напрямую выражают точность ограничения.

### Передавать quota и period напрямую

Отклонено для пользовательского CLI: это низкоуровневые cgroup details, которые не должны быть обязательными для обычного запуска.

### Разрешить все форматы Docker

Отклонено: совместимость с Docker CLI не является целью MVP.

## Критерии готовности

- parser корректно обрабатывает выбранные memory units;
- parser CPU переводит millicores в quota/period без floating point;
- parser отклоняет overflow и некорректные значения;
- отсутствие limit отличается от zero value;
- config layer не знает о файловых путях cgroup;
- unit tests покрывают valid, invalid и boundary values.
